# NoteNest — ad-free notes & PDF workspace

NoteNest is an offline-first, ad-free starter implementation for Android and Windows/web. It includes a note library, folders, typed notes, freehand ink tools, PDF import/viewing and page annotations, page templates, image attachments, search, dark mode, local autosave, and JSON backup/export.

## What is implemented
- **Local-first storage:** notes and folders are stored in IndexedDB on the current browser/app installation.
- **Notes library:** create notes, search titles/body, star notes, filter PDFs/handwritten notes, sort, create folders and move notes.
- **Editor:** typed text, pen, highlighter, eraser, ink color/size, undo/redo for note ink, plain/lined/grid/dotted templates.
- **PDFs:** import a PDF, render pages with PDF.js, move between pages, draw annotations on pages, export the original PDF.
- **Images:** attach image files to notes.
- **Export/import:** Markdown export for text notes; JSON backup contains notes, image attachments, PDF bytes and annotations. Import a JSON backup from the browser console using the `importBackup` function is not currently exposed in the UI.
- **Dark mode:** preference is saved locally.
- **PWA shell:** installable web app and service worker for app-shell caching.
- **Capacitor setup:** wrapper configuration for an Android APK build.

## Important limitations (current MVP)
- This is a functional MVP, not a full Samsung Notes clone. Handwriting is freehand canvas ink; it does not yet include handwriting-to-text, shape recognition, audio recording, OCR, or Samsung Notes file import.
- PDF annotations are stored in the NoteNest backup, not embedded into the original PDF. Exporting a PDF currently exports the original PDF bytes.
- Local IndexedDB storage is device/browser-specific. **Cloud sync is not configured yet**; see the roadmap below. Do not treat a backup file as cloud sync.
- The app does not include ads or analytics. A Google Fonts import is used for typography; the app falls back to system fonts if unavailable. To keep every asset local/offline, remove the `@import` line from `src/style.css`.
- Test large PDFs and images before relying on the app for important documents. Keep regular JSON backups.

## Run on Windows
1. Install Node.js LTS (includes npm).
2. Extract this project and open PowerShell/Terminal in the `NoteNest` folder.
3. Run:
   ```bash
   npm install
   npm run dev
   ```
4. Open the local URL Vite prints (usually `http://localhost:5173`).

For a production web build:
```bash
npm run build
npm run preview
```
Deploy the `dist/` folder to an HTTPS static host to use the PWA install flow. HTTPS (or localhost) is required for service workers.

## Build an Android APK
You need Node.js LTS and Android Studio with the Android SDK installed.
```bash
npm install
npm run build
npm run android:init
npm run android:sync
npm run android:open
```
Android Studio opens the generated project. Choose **Build > Build Bundle(s) / APK(s) > Build APK(s)**. The APK is generated by Android Studio; this source ZIP does not include a prebuilt APK.

If you need to regenerate the Android project later, keep a backup before running `npm run android:init`; the generated `android/` folder is intentionally not included in this source archive.

## Backup and recovery
Use **Export backup** to download `notenest-backup.json**.** Keep this file somewhere safe. It can contain personal notes and embedded PDF/image data, so protect it like your documents.

## Roadmap for cloud sync
Cloud sync is intentionally not silently enabled. A production cloud version should add:
1. A user-selected sync provider or authenticated backend (for example, Supabase).
2. End-to-end encryption or clear privacy controls before uploading note contents.
3. Conflict resolution for edits made on two devices.
4. A visible sync state and recovery/export tools.
5. Tests for large PDFs, interrupted uploads, offline changes, and account deletion.

Do not put private service-role keys in a client app. For a Supabase implementation, use a public anon key with row-level security and authenticated users, or a server you control.


## Build an APK with GitHub Actions (no Android Studio required)

1. Create a GitHub repository and upload the contents of this `NoteNest` folder (including `.github/workflows/android-apk.yml`) to the repository's root.
2. Open the repository's **Actions** tab and enable Actions if prompted.
3. The workflow starts on a push to `main`. You can also open **Actions → Build NoteNest Android APK → Run workflow**.
4. Wait for the workflow to finish with a green check. Open that run and download the **NoteNest-debug-apk** artifact. Extract the downloaded artifact ZIP to get `app-debug.apk`.
5. Transfer `app-debug.apk` to your Android phone and install it. This is a debug APK for personal testing, not a Play Store release build.

The workflow generates the Android wrapper during the cloud build; it does not commit the generated `android/` directory back into the repository. The first build may take several minutes. Review the Actions logs if it fails.
